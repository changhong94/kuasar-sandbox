# Kuasar / CubeSandbox 单节点对比

[English](README.md)

本目录重测现有的独立测试部署，不安装、升级或清空产品服务，不执行双节点测试。
完整命令见英文说明。使用新的时间戳结果目录，各阶段顺序执行。

## 顺序

1. prepare.py storage：低／高熵内存、独立沙箱相同／不同内容。每个沙箱
   64 MiB 文件、256 MiB 内存。低熵只改变内存，文件始终为高熵。
2. run.py --stage memory：恢复简单命令就绪、完整访问工作集、稳定运行时，
   分别采集沙箱与平台 PSS，以及原始 cgroup、主机内存和 I/O。
3. run.py --stage cache：并发 1／4，热缓存／文件页缓存冷却建议，
   Kuasar off／memory，Cube 默认行为。预热不纳入统计。
4. run.py --stage density：逐级增加实例，记录实际内存、数据空间、
   恢复与完整业务耗时，以及各延迟门槛下的观测通过比例。

先用 prepare.py config 指定私有 access 文件和 XFS 路径，检查目录配置，
再用 prepare.py fixtures 创建并验证新快照。基础模板应同为 2 vCPU／2 GiB。
更换部署布局时须调整平台进程和容器识别规则。这不是一键安装器。

extent_paths 用于保留快照；live_extent_paths 用于活跃实例，必须包含 Kuasar
可写差分文件所在的运行目录（默认 kuasar/runs）。只看 Store 的增长会漏计活跃写入。

report.py 从结果目录重新生成 JSON、CSV、SVG，不需要重新执行负载。
storage_report.py 汇总存储矩阵；plot.py 可选生成 Matplotlib PNG／SVG。
reproduce.py --config 配置文件 --output-root 结果根目录 可依次重跑整个单节点流程。

密度阶段先采集只读工作集，再用各实例不同的值改写内存中的每个 4 KiB 页，
并新增独立的 64 MiB 文件，分别展示共享收益与写入后的成本。

## 口径

- ready_ms：请求创建快照实例，到 SDK 简单命令成功。
- full_touch_ms：同一起点到完整内存和文件哈希校验结束，包含计算、SDK、
  命令和网络开销。不是纯虚拟机恢复耗时。两套 API 协议不同，不扣除开销。
- 内存诊断插入了读取前采样，其耗时不作为性能对照。
- 沙箱 PSS 与平台 PSS 分开。原始 cgroup 父子层级不可直接累加。
  PSS 不包含所有未映射页缓存和内核开销；名义额度与实际占用分别报告。
- 当前 Kuasar 平台 PSS 小计按 release-bin 进程选择，不包含位于其他目录的
  Zot；采集的 preparation 服务 cgroup 已包含其记账。评估整个部署成本时
  应结合原始进程范围和 cgroup 记录，不能把这个 PSS 小计当作所有平台开销。
- CPU／进程 I/O 可能遗漏短命进程。逻辑取数与物理读盘字节分别报告，
  Cube 缺少的逻辑指标记为缺失，不能写成零。
- file-advised-cold 只对实验文件执行页缓存回收建议，保留应用和设备缓存；
  不等于全栈冷缓存，不执行影响其他用户的全机清缓存。
- loop 镜像所在的外层文件系统缓存也保留，进程 read_bytes 是内核记账的
  存储读取量，不能据此断言 SSD 实际读取了同样多的数据。
- 物理区间统计避免重复计算 reflink，共享块计一次，排除缓存、支持数据库和
  文件系统元数据。它是指定目录的数据增量，不是平台全部磁盘成本。
- Kuasar memory 必须有预取启动日志。Cube 的 off 标签表示未发送 Kuasar
  专有选项，不代表关闭 Cube 自身所有预读。
- 样本 p95 和门槛通过比例仅为观测值，测试到 12 个实例不代表最大密度为 12。
  启动失败或达到内存保护条件时保留结果，停止提高该组数量。

保留种子、版本、配置和失败记录；新种子可避免与旧 Store 中的数据重复。
只清理本次实例和临时导出，保留发布快照。不要分享或提交含密钥的 access 文件，
也不要并行启动多个测试套件。
